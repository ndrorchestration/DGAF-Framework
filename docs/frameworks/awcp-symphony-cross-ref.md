## Agent Workspace Collaboration Protocol (AWCP)

The historical material describes AWCP as a workspace-delegation protocol between a
Delegator and Executor, with files-as-interface, lifecycle/session state machines, and
anchoring concepts. These are useful **design candidates**, not current implementation
facts in DGAF.

The claim that AWCP is the first protocol to formalize workspace delegation is
**NOT ESTABLISHED** here. A priority/novelty claim requires an external literature and
provenance review; a project-authored research outline cannot establish it by assertion.

| Historical AWCP concept | Current disposition |
|---|---|
| Delegator → Executor workspace projection | Candidate execution-contract / runtime-adapter pattern |
| Files as interface | Candidate grounding and workspace-contract pattern |
| 9-state lifecycle | Historical/provisional state-machine design; requires owning specification and tests |
| 4-state session model | Historical/provisional session model; requires owning specification and tests |
| Recursive anchoring | Map intent to current state/provenance/recovery controls; do not create parallel authority |

The historical **69.6% reduction in coordination failures** is **NOT ESTABLISHED as an
AWCP or DGAF result** by the cited outline. Any future promotion requires the owning
study, exact system/version, comparator, task set, execution record, derivation of the
metric, and retained evidence. A result reported for another protocol cannot be silently
transferred to AWCP merely because the lifecycle concepts are described as similar.

## Retained design value

The useful engineering questions survive without the unsupported authority or efficacy
claims:

- how to delegate a workspace with explicit scope and state;
- how to preserve file/version provenance during delegated execution;
- how to define lifecycle transitions and recovery semantics;
- how to match capability to task requirements;
- how to aggregate independent outputs without conflating consensus with truth;
- how to test centralized and decentralized routing against explicit comparators.

These should be implemented, if warranted, through current owners rather than by
reviving AWCP or Symphony as parallel control planes by name.
