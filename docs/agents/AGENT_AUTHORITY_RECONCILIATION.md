**Disposition:** Guarded source changes require formal reconciliation. Historical role/ID records remain provenance-bearing.

**Disposition:** Preserve specialist gate ownership while treating Layer 0 as cross-cutting constraints. Do not invent a single exclusive owner for all Layer-0 semantics.

### R-003 — Sentinel / Sentinel-Phi identity continuity

`FORMATION_TOPOLOGY.md` identifies Sentinel-Phi (A-12-φ) as the strategic security seat, while older materials use Sentinel and legacy formation language.

**Disposition:** Treat naming continuity and authority continuity as separate fields. Historical aliases do not create additional authority or active seats.

### R-004 — ID / formation drift

**Disposition:** IDs require explicit canonical lineage/alias semantics before automated joins or authorization checks depend on them.

### R-005 — Individual contracts contain legacy role language

Individual specs registered earlier than the later topology may contain older authority terminology.

**Disposition:** Reconcile one agent contract at a time, preserving provenance and requiring governing sign-off for material authority changes.

### R-006 — Public/IP visibility is governed separately

`PROPRIETARY.md` separates PUBLIC, FRAMEWORK, and SOVEREIGN content and NDR-133 controls.

**Disposition:** Classification, disclosure, public comprehension, and IP/security boundaries remain intersecting but distinct controls.

### R-007 — Taxonomy authority must not become experimental authorization

**Disposition:** Experimental control must use the exact candidate/deployment/workflow/artifact identity chain maintained by the P1–P9 control surfaces.

`P-35` is the Procluding Premise Gate. `P-42` is Adaptive Harmonic Governance. The current engineering remediation adds an explicit premise-check dependency at the DGAF/TGL/ConsensusTask boundary.

**Disposition:** Treat the explicit checker as an engineering/wiring dependency. Do not infer a PDMAL-specific constitutional premise policy from the wiring remediation.

### R-009 — Transversal agreement

Current live state is represented simultaneously by GitHub candidate/control records, CI/evidence artifacts, Vercel deployment metadata, Notion control state, taxonomy, vocabulary, and pattern registries.

**Disposition:** These projections must resolve to the same scoped candidate identity before downstream evidence is treated as current. Historical or role-different records remain valid only within their explicit scope.
