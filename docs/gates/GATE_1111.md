## Rationale

Artifacts that are technically correct can still fail on epistemic, ethical, or historical grounds. A mathematically coherent claim can be epistemically dishonest (overstated confidence), non-violative on its surface but harmful in context, or historically sequential in isolation but contradicting established prior art in the registry. The 1-1-1-1 Gate evaluates four orthogonal project-local quality dimensions; no single strong pillar compensates for another failing pillar.

The gate is named 1-1-1-1 because each pillar scores on a binary pass/fail per run (1 = pass, 0 = fail), with an example threshold of ≥ 3/4 passes per pillar over N ≥ 3 runs. The threshold is a protocol parameter, not a universal statistical law, and must not be described as empirically optimal without a calibration study.

## The Four Pillars

| Pillar | Label | Question | Failure Mode |
|--------|-------|----------|--------------|
| **1** | Mathematically Coherent | Is every quantitative claim internally consistent and derivable? | Numeric contradiction, undefined variable, broken formula |
| **2** | Epistemically Honest | Are confidence levels accurate? Is uncertainty disclosed? | Overstatement, hidden assumptions, false precision |
| **3** | Non-Violative | Does the artifact respect project ethical/safety constraints? | Constraint breach, security exposure, sovereignty violation |
| **4** | Historically Sequential | Is the artifact consistent with the established project provenance chain? | Contradicting prior artifact, broken changelog lineage, orphaned reference |

## Passing State

A PASS means the current gate run produced evidence satisfying the applicable project-local criteria. It does not automatically establish independent verification, validation, production readiness, regulatory compliance, or general efficacy.

```json
{
  "gate": "GATE-1111",
  "status": "PASS",
  "scope": "project-local gate procedure",
  "runs": 3,
  "threshold": "3/4 per pillar",
  "independent_certification": false,
  "timestamp": "YYYY-MM-DDTHH:MM:SSZ"
}
```

## Failing State

Any applicable pillar failure blocks project-local promotion until remediation and a fresh run.

```json
{
  "gate": "GATE-1111",
  "status": "FAIL",
  "scope": "project-local gate procedure",
  "failing_pillar": "epistemically_honest",
  "independent_certification": false,
  "timestamp": "YYYY-MM-DDTHH:MM:SSZ"
}
```

## Recovery Protocol

1. Identify the failing pillar and evidence.
2. Apply pillar-specific remediation.
3. Re-run with fresh evidence; do not reuse stale scores.
4. Preserve historical results and remediation evidence.
5. If the criterion itself is inadequate, revise the protocol instead of forcing a PASS.

## Epistemic Boundary

A successful run of this gate must not be used alone to claim:

- mathematical proof of convergence or universal stability;
- empirical superiority on real workloads;
- production readiness outside the tested scope;
- regulatory or standards compliance;
- official DGAF certification or endorsement;
- universal safety, security, or business-performance guarantees.

Those claims require their own evidence and claim-specific status.
